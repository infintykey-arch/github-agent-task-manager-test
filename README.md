# TaskWake

تطبيق Android أصلي صغير لإدارة المهام والتذكيرات، مكتوب بـKotlin وواجهة Android تقليدية. تُحفظ المهام محليًا باستخدام Room، ولا يحتاج التطبيق إلى حساب أو اتصال شبكي.

## الوظائف

- إضافة مهمة بعنوان ووصف اختياري، مع موعد تذكير اختياري.
- عرض المهام القادمة والمكتملة، وإكمال المهمة أو حذفها.
- حفظ المهام محليًا بين مرات تشغيل التطبيق.
- جدولة تنبيه محلي باستخدام `AlarmManager.setAndAllowWhileIdle` وإلغاء المنبه عند الإكمال أو الحذف.
- طلب صلاحية `POST_NOTIFICATIONS` وقت التشغيل على Android 13 وما بعده، وعرض حالة الإشعارات داخل الواجهة.
- إعادة جدولة المواعيد المستقبلية غير المكتملة بعد إعادة تشغيل الجهاز أو استبدال التطبيق.

## البناء والاختبار

يفتح المشروع في Android Studio، ويستخدم Android Gradle Plugin 8.9.2 وGradle Wrapper 8.11.1 وKotlin 2.1.20 وJDK 17 وAndroid SDK 35. يتولى GitHub Actions تثبيت Gradle وSDK؛ ولا يتطلب بناء Debug مفتاح توقيع إنتاجيًا.

ينفذ سير العمل `.github/workflows/android-apk.yml` اختبارات JVM، ثم يبني `app-debug.apk` ويتحقق من وجوده، ثم يثبّت APK التطبيق والاختبارات على محاكي API 35 ويشغّل `AndroidJUnitRunner` مباشرة عبر ADB. إذا نجح البناء يُرفع APK كأثر باسم **TaskWake-debug-apk** حتى إذا فشل اختبار المحاكي؛ تظل نتيجة الـWorkflow نفسها فاشلة عندها ولا تُعرض الاختبارات الفاشلة على أنها ناجحة. عند فشل instrumentation يحفظ التشغيل أيضًا سجلات التثبيت والاختبار وlogcat في **TaskWake-android-test-diagnostics**. لتنزيل الملفات: افتح تبويب **Actions** في المستودع، واختر التشغيل المعني، ثم نزّل الأثر المناسب من قسم Artifacts. يحتفظ GitHub بالأثر 14 يومًا.

تغطي الاختبارات قواعد قبول المواعيد المستقبلية ومنطق رفض الإشعارات عند غياب الإذن أو تعطيلها، وإنشاء المهام وتحديثها وحذفها واستعادتها بعد إعادة فتح قاعدة البيانات، وتصفية التذكيرات اللازمة لإعادتها بعد الإقلاع. وعلى المحاكي، تتحقق اختبارات منفصلة من مسار إنشاء PendingIntent للتذكير وإلغائه. هذه الاختبارات لا تثبت دقة تسليم الإشعار أو سلوك شاشة القفل على جهاز فعلي.

## دقة الإشعار وشاشة القفل والطاقة

يستخدم التطبيق منبهًا غير دقيق مسموحًا به (`setAndAllowWhileIdle`) لا `setExact`، ولا يطلب صلاحية المنبه الدقيق الخاصة. لذلك قد يتأخر الإشعار بسبب Doze أو قيود النظام أو الشركة المصنّعة، ولا يضمن التطبيق التنفيذ في الثانية المحددة. لا يوجد `USE_FULL_SCREEN_INTENT` ولا واجهة تقفز فوق شاشة القفل ولا `WakeLock` لإضاءة الشاشة. قد يصدر النظام صوتًا/اهتزازًا أو يضيء الشاشة حسب إعدادات القناة والجهاز، لكن ذلك غير مضمون.

قناة الإشعار خاصة (`VISIBILITY_PRIVATE`): يقرر المستخدم من إعدادات النظام ما إذا كان محتوى الإشعار ظاهرًا على شاشة القفل أو مخفيًا. ظهور إشعار على شاشة القفل مختلف عن إيقاظ الشاشة، وكلاهما مختلف عن فتح واجهة كاملة فوق شاشة القفل. التطبيق لا يتجاوز قفل الجهاز ولا يطلب مصادقة أو يفتح الجهاز تلقائيًا. إذا رُفضت صلاحية الإشعارات أو عطّلها المستخدم، فلن تظهر التنبيهات إلى أن يسمح بها؛ ولا يضمن التطبيق استرجاع تذكير فات موعده بعد منح الصلاحية لاحقًا.

تُعاد جدولة المواعيد المستقبلية بعد بث الإقلاع إذا لم تمنع قيود النظام أو الشركة المصنّعة ذلك. يلزم عمليًا اختبار الإشعارات وشاشة القفل على جهاز فعلي مضبوط لإعدادات المستخدم، ولم يتم الادعاء بإجراء هذا الاختبار بواسطة المحاكي وحده.

## اختبار يدوي مقترح على جهاز Android

1. ثبّت APK من أثر Actions واسمح بالإشعارات عند الطلب.
2. أنشئ مهمة بتذكير بعد دقائق، ثم تحقق من العنوان والوصف عند وصول الإشعار.
3. كرر الاختبار بعد رفض الإذن، ثم فعّله من إعدادات التطبيق، وتحقق من رسالة الحالة.
4. افحص إعدادات قناة «تذكيرات المهام» وإعدادات خصوصية شاشة القفل، مع الجهاز مقفلًا.
5. أعد تشغيل الجهاز وتحقق من إعادة الجدولة بعد فتحه، ثم اختبر الإكمال والحذف قبل الموعد.

لا يغني الاختبار اليدوي عن إعدادات الشركات المصنّعة أو سياسات توفير الطاقة، ولا تضمن نتيجة على جهاز تعميم السلوك على جميع أجهزة Android.
